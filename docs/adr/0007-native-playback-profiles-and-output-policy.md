# Native playback profiles and output policy

Native Playback treats Output Mode and Processing Profile as independent selectors. Direct Profile disables ReplayGain, EQ, and software volume changes and reports whether decoded and output parameters match; Processed Profile permits those transformations and labels the output accordingly. Changing software volume or enabling EQ while Direct is active switches to Processed with a brief notice. ReplayGain defaults off; enabling it once asks for album or track mode, stores that device-local choice, and shows whether the current file contains matching ReplayGain Metadata. The Music Server indexes that metadata so both Web and Desktop Clients can display it. Processed provides a ten-band graphic EQ with presets. Gapless playback uses mpv's weak mode so the Output Device can reopen when source parameters change rather than resampling later Tracks to the first Track's rate. The next Queue Track is appended to mpv's playlist shortly before the current one ends, so a natural boundary between Tracks of the same format keeps the Output Device open.

Linux exposes three user-facing output modes in a compact Player Bar menu. **Normal** submits source parameters to PipeWire and follows the operating system's active output. **Exclusive** resolves that same active PipeWire sink to its raw ALSA `hw:` device and opens it without PipeWire or ALSA conversion plugins. It does not ask the user to select a device and does not use mpv's unsupported ALSA exclusive flag. Bluetooth and other outputs without a raw ALSA mapping cannot use Exclusive; the Desktop Client reports the limitation and keeps Normal active. Hardware-busy, unsupported-format, resolution, or persistence failures also recover to Normal instead of displaying an Exclusive state that was not established. Exclusive and Adaptive keep mpv at full volume: on entry the software volume moves onto the device's own volume control (the raw ALSA card's playback control, or the PipeWire default sink), rounded to 0.5 dB so PipeWire adds no software remainder, and comes back when the mode is left or the Desktop Client exits. If the device cannot absorb all of it, mpv keeps its volume, so loudness never jumps. **Adaptive** temporarily forces the PipeWire graph to each source sample rate and resets the force setting when disabled, when the Desktop Client exits, or during recovery after an abnormal exit. If the Output Device cannot follow the graph rate, playback continues while Playback Telemetry reports device conversion. Compressed surround passthrough is excluded from the first native release because the Music Server does not currently index applicable formats.

## Consequences

The Player Bar shows the active output mode as a text button. One click opens a tightly spaced menu immediately above it with Normal, Exclusive, and Adaptive in that order. No output-device picker is presented. Selecting Adaptive applies it immediately with the same single-selection interaction as Normal and Exclusive. Detailed processing and playback telemetry remain internal state and may be exposed through a future diagnostic surface, but the mode selector does not present inferred signal-path data or an unprovable bit-perfect badge.
